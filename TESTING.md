## Обнаруженные требования к тестовому стенду

Даже dry-run требует `--qnum`. В штатных настройках номер назначает Forkop,
пресеты не должны его переопределять. Списки должны быть доступны после снижения
привилегий nfqws (root-owned 0644, каталоги 0755). Изначальные ошибки проверки
из-за отсутствия qnum и прав 0600 устранены в тестовом стенде, а не в стратегиях.

Три пользовательских списка upstream создаются пустыми для новой установки:
`list-general-user.txt`, `list-exclude-user.txt`, `ipset-exclude-user.txt`.
Их нельзя перезаписывать при обновлении уже установленного пакета.

## DNS-конфликт при ручной сетевой проверке

Пользователь сообщил, что YouTube/Discord не работают. На TR3000 запросы через
AdGuard → dnsmasq → основной роутер возвращали чужие FakeIP 198.18.0.0/15;
sing-box TR3000 фиксировал `missing fakeip record`.
Исправление стенда: DNS Forkop переведён на DoH, dnsmasq направлен на локальный
DNS Forkop 127.0.0.42, кэш AdGuard сброшен перезапуском. После этого DNS дал
реальные IP обоих сервисов, HTTPS-запросы с TR3000 получили 200.
Это не подтверждает голос Discord или воспроизведение видео с LAN-клиента.

Пакет пока не управляет интеграцией внешнего AdGuard/dnsmasq. Перед публичным
релизом необходим учёт DNS-зависимостей при применении и откате: нельзя
остановить Forkop, оставив dnsmasq направленным на его неработающий listener.

## Прерывание LuCI и блокировка

После запуска через синхронный RPC переключение оборвалось: процесса уже нет,
пустая lock-директория осталась, active=ALT13 при UCI=ALT12. Проверена контрольная
сумма previous.uci против applied.sha256, последняя согласованная конфигурация
восстановлена. Сам факт тайм-аута RPC не зафиксирован отдельно; это вероятная
причина прерывания, а несогласованность подтверждена непосредственно.

LuCI переведён на `start` → фоновый `setsid` worker с опросом состояния/журнала.
В прошивке нет nohup, поэтому он не используется. Блокировка хранит PID;
живой владелец блокирует повторный запуск, мёртвый допускает очистку известных
файлов блокировки. Некорректная блокировка без PID требует ручной проверки.
